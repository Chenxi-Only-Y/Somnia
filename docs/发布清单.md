# 发布清单

打包给别人之前，逐条过一遍。漏一条就可能把私人的东西带出去。

## 1. 不能进包的东西

| 路径 | 里面是什么 | 处理 |
|---|---|---|
| `data/` | 对话库、密钥、账号、备份 | **删掉**（`clean.bat` 会处理） |
| `memory/archive/` | 归档的原话 | **删掉** |
| `wechatauto_logs/` | 微信操作日志（含会话痕迹） | **删掉** |
| `stickers/` | 随包发的 91 张表情包 | **保留**（`clean.bat` 不会删） |
| `photos/` | 你自己生成/拍的照片 | **删掉** |
| `persona/persona.md` | 你写的那个人 | **删掉**，只留 `persona.example.md` |

`data/settings.json` 里有三样绝对不能外泄：`api_key`、`account`、`target_id`。

## 2. 打包前跑一次

```bat
clean.bat
```

它会清掉上面这些运行期产物。跑完再确认：

```bash
dir            # 不应该有 data / memory / wechatauto_logs / stickers / photos
git status     # 不应该出现被忽略之外的新文件
```

## 3. 首次运行的样子（给用户看的）

```
python -m somnia.panel
→ 不会自动接微信（没存过设置时，故意不启动）
→ 页面上填：API 地址、密钥、模型、通道
→ 点「唤醒」
```

人设是空的，**而且默认不参与对话**（prompt 里只有 `SOUL.md` 的硬规则）。
要角色得做两件事：复制 `persona/persona.example.md` 成 `persona.md` 写内容，
再把 `somnia.toml` 里的 `[identity] prompt_persona` 改成 `true`。

发布说明里必须写这一条，否则用户会以为"写了人设没生效"。

## 4. 环境与依赖

- **Python 3.11 以上**。3.10 没有 `tomllib`，`somnia.toml` 会被整份忽略（启动时会有提示）。
- Windows 10/11：接微信必须；只用 `cli` 通道则任何系统都行。

### 第三方包

```bash
pip install -r requirements.txt
```

核心是**零依赖**（纯标准库）。`wechatauto-replica` 只有走微信真机通道时才需要：

```bash
pip install wechatauto-replica
```

## 5. 合规与风险（写进发布说明里）

- **单用户自用**。不要做成对外服务或给别人批量用。
- **AI 身份**：程序里默认带「ta 不是人」的常驻横幅和启动提示，别删。
- **微信真机通道**：`wechatauto-replica` 会往 `Weixin.dll` 的进程内存写 1 个字节打开无障碍闸门。
  这是内存补丁，属于非官方操作，发布时必须写清三件事：
  1. 非官方接口，**有封号风险**
  2. **有概率导致微信意外登出**（要重新扫码，聊天记录不丢）
  3. 建议先小号试用；出问题先「睡下」，再重新登录，或卸载该包退回 `cli`
- **表情包版权**：呆猫八条、这狗都是他人作品，随包分发由你自己判断风险；
  正式发布建议换成自己画的，或者只留 `notes.json` 那套备注格式。
- **内容边界**：涉政涉黄涉赌涉暴、教唆自残，`SOUL.md` 里有硬规则拦着，别改掉。
- **不要宣传成"AI 女友/女友模拟器"**：定位是"一个话不多的人"，这决定了它的行为边界。

## 6. 发新版（让用户能一键更新）

当前走的是「GitHub tag 当发布包」，不用额外托管：

```bash
# 1. 改版本号（两处必须一致）
#    somnia/__init__.py 的 __version__
#    pyproject.toml 的 version
# 2. 更新 CHANGELOG.md
python tests/run_all.py          # 3. 全绿

git add -A
git commit -m "0.2.1"
git tag -a v0.2.1 -m "0.2.1"     # 4. 打标签
git push origin main --follow-tags

# 5. 改 version.json，把数字和 zip 指向新 tag
#    zip 固定格式：https://github.com/USER/REPO/archive/refs/tags/v0.2.1.zip
git add version.json
git commit -m "chore: 指向 v0.2.1"
git push
```

用户端下次打开面板，左下角就会冒出 `↓ 新版本 0.2.1`，点一下自己就更新了。

`version.json`（放在仓库根目录，走 raw 链接）：

```json
{
  "version": "0.2.1",
  "zip": "https://github.com/<你的账号>/Somnia/archive/refs/tags/v0.2.1.zip",
  "notes": "修了发送重复；模型名换成 deepseek-flash"
}
```

**为什么用 tag 归档而不是自己传 zip**：GitHub 的 `archive/refs/tags/*.zip` 只包含 git 里的文件，
天然不带 `data/`、`persona.md` 这些；更新脚本也认这种多套一层目录的结构。

不想用 GitHub 也行：`zip` 填任何可下载地址，`version.json` 放任何能直连的地方。
